# デザイン批評: Time Machine Viewer（2026-11-01）

design-critique の枠組みで、作り直し前の画面（概要、推移、ディレクトリ、診断）を見た記録です。用途は、遅いバックアップがどこで時間を使っているかを、本人が一目でつかむことです。段階は試作から仕上げへの途中にあたります。

## 全体の印象

数値はそろっているものの、画面の並びが作った順のままで、いちばん知りたい「どこで時間がかかっているか」に目が届くまでに、段階名、進捗バー、警告の英文、処理中のパスを読み進める必要があります。同じ数字が三つのカードに重複し、概要は縦に長くスクロールしないと全体が見えません。

## 使いやすさ

| 気づいたこと | 重さ | 直し方 |
|---|---|---|
| 主役であるボトルネックの指標が、段階名と警告の英文に挟まれて目立たない | 重い | 指標を見出しの直下に横並びのタイルとして置き、最初の視線で読めるようにする |
| 引き継ぎ件数、1件あたりの時間、転送速度が「どこで時間が」「引き継ぎ」「内訳」の三カードに重複している | 重い | 一か所にまとめ、細かい数値は折りたためる「詳しい数値」に移す |
| 診断の結果が別タブにあり、しかもアプリを開き直すと消える | 重い | 概要にも最後の診断結果を出し、記録ファイルから結果を読み直して残す |
| 警告カードが backupd の英文をそのまま3行ずつ並べ、画面の三分の一を占める | 中くらい | 一件一行の日本語の見出しにし、英文はマウスを重ねたときに出す |
| 推移の件数グラフが試行の切り替わりで跳ね、普段の動きが底に潰れて読めない | 中くらい | 試行をまたぐ区間を除き、縦軸を外れ値に引っ張られない範囲に収める |
| 推移の各グラフで横軸の範囲がばらばらで、SMB のグラフは数秒分しかない | 中くらい | すべてのグラフで同じ時間範囲を使い、範囲を選べるようにする。SMB は1分ごとにならす |
| 進捗が 25.6%、容量 7%、項目 8%、変更箇所 62% と四通り出て、どれを信じればよいか分からない | 中くらい | 見出しは全体の進捗だけにし、残りは詳しい数値に入れて意味を添える |

## 見た目の階層

- 最初に目に入るもの: 「コピー中」の大見出しと進捗バー。状態は分かるが、知りたいことの答えではない
- 読む順: 見出し、警告、処理中の場所、引き継ぎ、内訳と縦一列に下りるだけで、どれも同じ重さの枠に入っている
- 強調: 1件あたりの時間だけが大きな文字だが、他のタイルと並びが揃っておらず、比べる相手（往復時間や診断の open 時間）と離れている

## 一貫性

| 要素 | 問題 | 直し方 |
|---|---|---|
| 数値の書き方 | 「0.07 MB/s」「249 KB/s」「471 バイト /s」と単位の書き方が混在 | 速度は一つの書式に揃える |
| 枠 | すべて同じ GroupBox で、要約と詳細の区別がない | 要約はタイル、詳細は折りたたみと役割で形を変える |
| タブの並び | 概要の次がディレクトリで、ボトルネックを見る推移と診断が後ろにある | 概要、推移、診断、ディレクトリ、ログの順にする |

## アクセシビリティ

- 色のコントラスト: 本文と数値は十分。補足の灰色の小さな文字（12pt 前後）は暗い背景で読みにくい場面がある
- 押す場所の大きさ: ボタンは macOS 標準の大きさで問題なし
- 読みやすさ: 長い説明文がカードごとに入り、行が画面幅いっぱいに伸びて読みにくい。説明は短くし、詳しくはマウスを重ねたときの補足に回す

## よいところ

- 必要な情報源（tmutil、統合ログ、nettop、fs_usage）を一つの画面に集めており、他の道具を開かずに状況を追える
- 日本語の用語が揃っており、数値に単位と時点が添えてある
- ディレクトリの表は、滞在時間と割合で並び、どこに時間を使ったかが素直に読める

## 優先して直すこと

1. 概要をダッシュボードに組み直す。見出しを一行に縮め、その下に「1件あたりの時間」「処理件数」「SMB 通信」「バンドを開く時間（最後の診断）」の四つのタイルを推移の小さなグラフ付きで並べる。その下を二段に分け、左に処理中の場所、右に状態（警告を一行ずつ）を置き、残りは「詳しい数値」に折りたたむ
2. 推移を同じ時間範囲の二列のグラフにし、範囲を選べるようにする。試行の切り替わりの跳ねを除く
3. 診断の結果を記録ファイルから読み直して残し、概要のタイルからも測れるようにする
